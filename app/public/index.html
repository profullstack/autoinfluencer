Desktop environments

            
A desktop environment is a computer that does the browser work for you: posting to networks, recording your app, signing in once where a network asks. Add one, run the connector on it, and it stays connected.

            

              
              
              
            

            

            

          

          

            
How the two-way connection works

            
    
              
  1. Desktop → us. The connector (autoinfluencer desktop connect, or the desktop app) opens an outbound HTTPS long-poll to /api/v1/desktop/poll with the desktop's token. No ports are opened and it works behind NAT. The same token lets agents on that computer call every tool here as you (MCP and REST).
    2. 
              
  2. Us → desktop. Jobs (publish this post, open this page, record this app) come back down that same channel. The connector runs them through the local W3BS broker (127.0.0.1:7801/mcp), which drives the agent browser by DevTools: snapshot, click and fill by element, not screenshots. Results and frames go back to /api/v1/desktop/result.
    3. 
              
  3. The person stays in charge. The desktop asks once before an agent may drive, sign-ins, CAPTCHAs and payments are handed to the person (never solved by the agent), and the emergency stop (Super+Alt+Escape) ends it at once.
    4. 
            

            
For operators there is also the reverse SSH tunnel: our own fleet runs the server on dev2, and the desktop bonita keeps a reverse SSH tunnel (ssh -N -R …) open to dev2, so agents on dev2 reach bonita's desktop layer while bonita's connector polls dev2. That is the same two-way channel, with SSH carrying the server → desktop half.
